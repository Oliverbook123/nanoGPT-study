# 00 项目总览

## 这是什么

nanoGPT 是一个"能跑在小电脑上、代码最少的 GPT（生成式预训练 Transformer）"实现。它不是生产级框架，而是**教学范本**:把 GPT 的核心拆到最短、最可读。官方描述是"prioritizes teeth over education"——即优先保证能真正训练出结果，代码却依旧朴素易读。

- 全仓库核心代码就三个文件:
  - `model.py`:GPT 模型定义(330 行)
  - `train.py`:训练循环(336 行)
  - `sample.py` 推理采样(89 行)
- 它复现 GPT-2 (124M，官方标签口径；本项目默认配置实算 124.37M，见 [05_源码解读_model.md](./05_源码解读_model.md))，在 8×A100 上约 4 天训练到 loss≈2.85（仓库根 `README.md` 写 4 天，`config/train_gpt2.py` 注释写约 5 天）。

## 目录结构

| 路径 | 作用 |
|------|------|
| `model.py` | GPT 模型本体(LayerNorm, Attention, MLP, Block, GPT) |
| `train.py` | 训练主脚本(数据加载、loss、优化、调度、DDP、checkpoint) |
| `sample.py` | 加载模型 + 生成文本 |
| `configurator.py` | 极简配置覆盖机制(命令行参数/配置文件注入 globals) |
| `bench.py` | 纯前向/反向 benchmark，测速度 |
| `config/` | 各种训练配置 |
| `data/` | 数据集和预处理脚本 |

## 配置文件如何生效(有趣的设计)

`train.py` 顶部定义了一堆默认变量(如 `batch_size`、`learning_rate`)。然后:

```python
exec(open('configurator.py').read())  # 把命令行/配置文件的值覆盖进全局变量
```

`configurator.py` 遍历 `sys.argv`,遇到 `--key=value` 就用 `ast.literal_eval` 解析（并做 `assert type(attempt) == type(globals()[key])` 类型校验）后写回 `globals()`;遇到一个文件名(如 `config/train_shakespeare_char.py`)就 `exec` 那个文件。所以:

```bash
python train.py config/train_shakespeare_char.py --device=cpu
```

= 先加载 `config/train_shakespeare_char.py` 的配置,再覆盖 `device=cpu`。

## 三个运行模式 `init_from`

- `scratch`:从头随机初始化训练
- `resume`:从 `out_dir/ckpt.pt` 断点续练
- `gpt2*`(如 `gpt2-xl`):加载 OpenAI 预训练权重做微调

## 预处理 vs 训练 vs 推理 三步

1. `python data/<数据集>/prepare.py` → 生成 `train.bin`、`val.bin`、`meta.pkl`
2. `python train.py <config>` → 训练出 `out-xxx/ckpt.pt`
3. `python sample.py --out_dir=out-xxx` → 采样生成

## 设备选项(重要,新手常踩坑)

- `--device=cpu`:macbook 等无 N 卡机器
- `--device=mps`:Apple Silicon 用片上 GPU(快 2-3 倍)
- `--device=cuda` + `--compile=False`:老 PyTorch 或非 CUDA 环境
- `--compile=True`:PyTorch 2.0 `torch.compile`,明显提速但要新版
