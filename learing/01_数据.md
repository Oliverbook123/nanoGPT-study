# 01 数据：文本怎么变成模型能吃的东西

语言模型训练的本质是**预测下一个 token**。所以第一步是把"文本"转成"一串整数 id"。

## 两种 tokenization 方式

nanoGPT 提供了两套预处理，演示两种粒度的分词：

### 1. 字符级 (character-level) — `data/shakespeare_char/prepare.py`

最简单、最直观，适合新手入门。把"字符"当最小单位。

```python
chars = sorted(list(set(data)))         # 所有出现过的去重字符
stoi = { ch:i for i,ch in enumerate(chars) }   # 字符 -> id
itos = { i:ch for i,ch in enumerate(chars) }   # id -> 字符
def encode(s): return [stoi[c] for c in s]     # "Hi" -> [stoi['H'], stoi['i']]
def decode(l): return ''.join([itos[i] for i in l])
```

- Shakespeare 文本约 111 万字符，去重后 **vocab_size = 65**（换行符 `\n`、空格、标点 `!$&',-.3:;?`、大写 A-Z、小写 a-z，共 65 个）。
- `chars` 是按 Unicode 码位排序的，第一个字符是 `\n`（id=0），空格是 id=1，所以 `'a'` 的 id 实际是 39。
- 缺点：每个字符是一个 token，序列很长，模型要学很久。

### 2. BPE 子词级 (byte-pair encoding) — `data/openwebtext/prepare.py` 和 `data/shakespeare/prepare.py`

真实 GPT-2 用的方式。用 `tiktoken` 库把文本切成一堆"子词"（subword)，handle 常见词、标点、生僻词，vocab_size = 50257。

```python
import tiktoken
enc = tiktoken.get_encoding("gpt2")
ids = enc.encode_ordinary(text)   # 文本 -> id 序列（忽略特殊 token）
text = enc.decode(ids)            # id 序列 -> 文本
```

> **注意**：源码用的是 `encode_ordinary()` 而不是 `encode()`。`encode_ordinary()` 会**忽略特殊 token**（如 `enc.eot_token`），而 `encode()` 会对特殊 token 进行处理。

- 优点：序列更短、词表覆盖更广，是生产级别做法。
- `data/shakespeare/prepare.py` 也用 BPE，但跑在 tiny shakespeare 上，秒级完成。

### openwebtext 的额外步骤：文档分隔符

openwebtext 在每篇文档末尾追加了 `eot_token`（id=50256）作为文档分隔符：

```python
ids.append(enc.eot_token)  # add the end of text token, e.g. 50256 for gpt2 bpe
```

这是为了让模型知道"这篇文档结束了"，是 BPE tokenization 中重要的细节。

## 预处理输出的文件

运行 `python data/<数据集>/prepare.py` 后，输出因脚本而异：

| 文件 | 字符级脚本 | BPE 脚本 | 说明 |
|------|-----------|---------|------|
| `train.bin` | ✅ 生成 | ✅ 生成 | 训练集 token id 序列（`np.uint16` 二进制，一个超长一维数组） |
| `val.bin` | ✅ 生成 | ✅ 生成 | 验证集 token id 序列 |
| `meta.pkl` | ✅ 生成 | ❌ 不生成 | 仅**字符级**脚本生成（含 `vocab_size`, `itos`, `stoi`）；本仓库的 `hongloumeng/prepare.py` 也是字符级，同样会生成 |

> **重要**：`meta.pkl` 只有字符级脚本（`shakespeare_char/prepare.py`、本仓库的 `hongloumeng/prepare.py`）才生成。BPE 脚本（`shakespeare/`、`openwebtext/`）不需要它，因为词表在 tiktoken 库里自带。推理时 `sample.py` 会自动检测：有 `meta.pkl` 用字符编解码，没有就用 GPT-2 BPE。

> 注意：`train.bin` / `val.bin` 是**一串连续的整数**，不是"一行一条样本"。训练时再从中随机切出固定长度的块（block）。

**标签（target）不需要单独文件**：因为 GPT 是自回归的，`输入 x = 序列[i : i+block]`，`标签 y = 序列[i+1 : i+block+1]`——把输入整体右移一位就是标签。这正是 `get_batch` 在做的事，见 [03_训练.md](./03_训练.md)。

## 数据集划分方式

两种数据集的划分方式不同：

- **字符级 (shakespeare_char)**：前 90% 训练，后 10% 验证（顺序切分）。
  ```python
  train_data = data[:int(n*0.9)]
  val_data   = data[int(n*0.9):]
  ```
- **openwebtext**：用 HuggingFace 的 `train_test_split`，先 shuffle 再切出 **0.05%** 作为验证集（约 4007 篇文档），不是 10%。
  ```python
  split_dataset = dataset["train"].train_test_split(test_size=0.0005, seed=2357, shuffle=True)
  ```

## 为什么用 `uint16` 存储

token id 最大也就 5 万出头（GPT-2 词表 50257），`uint16` 上限 65535 足够装下，每个 token 只占 2 字节，省内存。加载时 `np.memmap` 内存映射，不用把整个文件读进 RAM，几十 GB 数据也能流畅跑。

## 数据层面的心智模型

```
你看到的文本         模型看到的东西
"Hello world"    →   token ids: [15496, 995]             (BPE)
"Hello world"    →   token ids: [20, 43, 50, 50, 53, 1, 61, 53, 56, 50, 42]  (字符级, 11个字符)
```

模型只学一件事：**给定前面的 id 序列，下一个 id 最可能是哪个**。
